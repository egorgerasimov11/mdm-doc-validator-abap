# ZMDMDOC — внедрение за 8 шагов

Одна линейная инструкция: от пустой системы до работающего валидатора документов
как Z-отчёта. Опциональное (Ollama, встраивание в MDG) — в конце, отдельно.

**Что нужно заранее:** ABAP ≥ 7.50 · [abapGit](https://abapgit.org) установлен ·
ключ разработчика или транспортный запрос.

Полная версия со всеми ветками и обоснованиями — [INTEGRATION.ru.md](INTEGRATION.ru.md).

---

## Шаг 1. Проверить зависимости

1. Транзакция **`SE24`**
2. В поле `Object Type` ввести `/UI2/CL_JSON` → нажать **Display**
3. Повторить для `CL_ABAP_GZIP`, затем для `CL_ABAP_ZIP`

**Ожидаем:** все три класса открываются.

**Если `/UI2/CL_JSON` не найден** — не блокер. Отключатся LLM, выгрузка JSON и
runtime-переопределение правил. Ядро (чтение PDF + regex + правила + вердикт) работает.

---

## Шаг 2. Создать пакет

1. Транзакция **`SE80`**
2. В выпадающем списке слева выбрать **`Package`**
3. Ввести `ZMDMDOC` → **Enter** → на вопрос о создании ответить **Yes**
4. Заполнить описание, Software Component `HOME`, назначить транспортный слой
   (для локального теста допустим пакет `$TMP` — без транспорта)

---

## Шаг 3. Импортировать код

1. Транзакция **`ZABAPGIT`** (или `SE38` → программа `ZABAPGIT_STANDALONE` → **Execute**)
2. Нажать **`+ New Online`**
3. Заполнить:
   - `Git repository URL` — адрес репозитория
   - `Package` — `ZMDMDOC`
   - `Branch` — `main`
4. Нажать **Create Online Repo**
5. Нажать **Pull**

**Ожидаем:** abapGit создаёт объекты пакета.

**Если нет доступа к git по HTTPS:** на шаге 2 выбрать **`+ New Offline`**, указать
пакет `ZMDMDOC`, затем **Import ZIP** и выбрать архив репозитория.

---

## Шаг 4. Активировать объекты

1. Транзакция **`SE80`**
2. Открыть пакет `ZMDMDOC`
3. Выделить все объекты → правый клик → **Activate**

**Ожидаем на системе с MDG:** активируется всё.

**Ожидаем на системе без MDG** (обычный ECC / S/4 без MDG): **8 объектов не активируются**,
потому что ссылаются на типы `USMD*`. Это нормально — оставьте их неактивными или удалите:

```
ZCL_MDMDOC_MDG_READER   ZCL_MDMDOC_MDG_MAP     ZCL_MDMDOC_MDG_CHECK
ZCL_MDMDOC_ONBOARD      ZCL_MDG_BP_FIELD_DERR_VAL
ZMDMDOC_SETUP           ZMDMDOC_DOCTOR         ZMDMDOC_MDG_DISCOVER
```

Ядро валидатора (`ZMDMDOC` + `ZMDMDOC_RULES` + базовые классы + `ZCL_MDMDOC_SELFTEST`)
активируется и полностью работает без них.

---

## Шаг 5. Прогнать юнит-тесты

1. Транзакция **`SE80`**
2. Открыть пакет `ZMDMDOC`
3. Правый клик по пакету → **Run** → **Unit Tests** (или `Ctrl+Shift+F10`)

**Ожидаем:** все тесты зелёные. Они `HARMLESS/SHORT` — без сети, без файлов, без SAP-данных.

**Если красные** — дальше не идти. Ищите причину в выводе теста.

---

## Шаг 6. Создать класс сообщений

1. Транзакция **`SE91`**
2. В поле `Message Class` ввести `ZMDMDOC` → нажать **Create**
3. Перейти на вкладку **Messages**
4. В строке с номером `001` ввести текст: `&1&2&3&4`
5. Нажать **Save** и активировать

**Зачем:** через него отчёт возвращает вердикт как сообщение (важно для фоновых заданий).

---

## Шаг 7. Первый запуск

1. Транзакция **`SA38`**
2. В поле `Program` ввести `ZMDMDOC` → нажать **Execute** (F8)
3. На экране выбора:
   - `p_file` — путь к тестовому PDF. В репозитории есть готовый эталон:
     скачайте `samples/sample_bank_letter.pdf` на свой ПК и укажите путь к нему
     (данные выдуманные, реальные вендоры не нужны)
   - оставить радиокнопку **ПК** (файл с вашего компьютера)
   - остальное не трогать (галка LLM снята → детерминированный путь без Ollama)
4. Нажать **Execute** (F8)

**Ожидаем на эталонном `sample_bank_letter.pdf`:** вердикт **`NEED_MANUAL_REVIEW`**,
findings `BNK-026` (NOTE — подпись не мокрая, но найден печатный блок должностного
лица), `BNK-023` и `BNK-025` (WARNING — держатель счёта и имя банка без LLM не
читаются; это честное поведение детерминированного ядра). Именно такой результат
означает, что импорт и активация прошли сквозняком. Полная таблица ожиданий (и
второй сэмпл `sample_invoice.pdf` → `REJECT`/`BNK-001`, он же тест inflate-пути) —
в [../samples/README.md](../samples/README.md).

**В общем случае:** отчёт с блоком `EXTRACTED DATA`, списком findings и вердиктом
(`ACCEPT` / `WARNING` / `NEED_MANUAL_REVIEW` / `REJECT`).

**Если «нет текста» / документ нечитаем:** это скан без текстового слоя. Ядро без LLM
их не читает — см. опцию A ниже.

---

## Шаг 8. Выдать роль оператору

1. Транзакция **`PFCG`**
2. Создать роль → вкладка **Authorizations** → добавить объекты:

| Объект | Значение | Зачем |
|---|---|---|
| `S_TCODE` | `SA38` | запуск отчёта |
| `S_GUI` | ACTVT `61` | чтение файла с ПК |
| `S_DATASET` | ACTVT `33`/`34`, PROGRAM `ZMDMDOC*` | только если файлы лежат на сервере приложений |

3. Сгенерировать профиль, назначить пользователям.

**Готово.** Валидатор работает как отчёт.

---

# Опциональные шаги

## Опция A — распознавание сканов (ваш локальный Ollama)

Нужно, только если приходят PDF-сканы без текстового слоя или картинки.

> **Интернета здесь нет.** Модель работает на вашем железе, документы не покидают ваш
> периметр. ABAP обращается к Ollama по HTTP, потому что Ollama — это сервер (даже на
> `localhost` это HTTP); никакого другого способа поговорить с моделью из ABAP не
> существует. Не включаете галочку LLM — сетевых вызовов нет вообще.

1. На хосте, **доступном с сервера приложений SAP** (не с вашего ПК!), установить Ollama
2. Выполнить: `ollama pull qwen3:4b` и `ollama pull qwen2.5vl:7b`
3. Запустить: `OLLAMA_HOST=0.0.0.0 ollama serve`
4. Транзакция **`SA38`** → `ZMDMDOC` → **Execute**
5. На экране выбора включить флажок LLM, в поле URL ввести `http://<хост>:11434`

**Важно:** SAP открывает соединение с **сервера приложений**. `localhost` сработает,
только если Ollama стоит на том же хосте. HTTP не требует настройки SM59/SICF.
Для HTTPS нужен CA-сертификат в **`STRUST`**.

Если Ollama недоступен — отчёт не падает, а выдаёт finding `LLM-001` и работает
в детерминированном режиме.

## Опция B — проверить готовность к MDG

Только на системе с MDG.

1. Транзакция **`SA38`**
2. Ввести `ZMDMDOC_SETUP` → **Execute**
3. Поле `p_model` оставить `BP`; `p_cr` — номер тестового Change Request (можно пусто)
4. **Execute**

**Ожидаем:** список проверок `PASS/FAIL/SKIP` и итог `N passed, M failed`.
Пока есть красное — к опции C не переходить.

## Опция C — встраивание в MDG (сверка заявки с документом)

⚠️ **Сейчас заблокировано.** Нужно сначала выяснить одну вещь на системе:
какая реализация BAdI `USMD_RULE_SERVICE` владеет фильтром `MODEL = BP`
без ограничения по `ENTITYTYPE`.

Порядок и обоснование — [MDG_SYSTEM_FACTS.md](MDG_SYSTEM_FACTS.md), раздел C.
Пошаговая инструкция по встраиванию — [INTEGRATION.ru.md](INTEGRATION.ru.md), глава 10.

Коротко: BAdI **не Multiple Use**, слот `BP` занят. Поэтому наш код вызывается
**двумя строками** из уже существующей реализации, а не регистрируется своей.

## Если что-то пошло не так

| Симптом | Куда смотреть |
|---|---|
| 8 объектов не активируются | Это норма без MDG — шаг 4 |
| Юнит-тесты красные | Не идти дальше; вывод теста |
| Сжатый PDF не читается | `ZMDMDOC_DOCTOR`: чеки inflate и codepage; INTEGRATION.ru.md §7 |
| Скан не распознаётся | Опция A (Ollama) |
| Ollama не отвечает | URL должен быть доступен **с сервера приложений**, не с ПК |
| Нужно поменять правило | [RULES.ru.md](RULES.ru.md) |
